COBERTURA ECT 2026 - NOTIFICACIONES PUSH
========================================

QUÉ HACE
--------
La versión incluida está preparada para:

A) 10 minutos antes de un curso:
- Si tiene Staff asignado: avisa a ese Staff.
- Si NO tiene Staff asignado: avisa a todo el Staff.

B) Cuando llega la hora de inicio:
- Si todavía NO se marcó "Marcar inicio", avisa al resto del Staff que hay un curso sin cubrir.

C) En la app:
- El Staff asignado puede tocar "Confirmar que voy a cubrir".


PARTE 1 - CREAR LA VAPID KEY
----------------------------
1. Firebase Console.
2. Configuración del proyecto (engranaje).
3. Cloud Messaging.
4. Buscá "Web Push certificates" / "Certificados push web".
5. Tocá "Generate key pair" / "Generar par de claves" si todavía no existe.
6. Copiá la clave pública.
7. Abrí config.js.
8. Reemplazá:

   vapidKey: "PEGAR_VAPID_KEY_AQUI"

   por:

   vapidKey: "LA_CLAVE_PUBLICA_QUE_COPIASTE"

9. Guardá y subí el cambio a GitHub.

La VAPID key pública puede estar en el frontend. NO pegues claves privadas ni Service Account JSON en GitHub.


PARTE 2 - ACTIVAR NOTIFICACIONES EN CADA CELULAR
------------------------------------------------
Con la app ya publicada en GitHub Pages (HTTPS):

1. Cada Staff inicia sesión en su celular.
2. En Cuenta toca "Activar notificaciones".
3. El navegador pregunta permiso.
4. Elegir Permitir.

El token del dispositivo queda guardado en Firestore en push_tokens.

Si una persona usa dos dispositivos, puede activar los avisos en ambos.


PARTE 3 - AVISOS CON LA APP ABIERTA
------------------------------------
La app incluye un respaldo local.
Si la página está abierta y el navegador dio permiso de notificaciones:
- avisa al Staff asignado alrededor de 10 minutos antes;
- si el curso comienza sin inicio marcado, avisa a los demás usuarios que tengan la app abierta.

Esto no necesita Cloud Functions.


PARTE 4 - AVISOS REALES CON LA APP CERRADA
-------------------------------------------
Para que Firebase revise la hora aunque nadie tenga la página abierta, hay que desplegar la función incluida en:

FUNCIONES_FIREBASE.zip (al extraerlo crea functions/index.js)

IMPORTANTE:
Firebase exige plan Blaze/facturación habilitada para desplegar Cloud Functions.
La función usa un único trabajo programado que se ejecuta cada minuto.


PARTE 5 - DESPLEGAR LA FUNCIÓN
------------------------------
Necesitás Node.js instalado.

Primero extraé FUNCIONES_FIREBASE.zip en la raíz del proyecto. Debe aparecer la carpeta functions/.

Desde una terminal en la carpeta del proyecto:

1. Instalar Firebase CLI (una sola vez):
   npm install -g firebase-tools

2. Iniciar sesión:
   firebase login

3. Verificar el proyecto:
   firebase use cobertura-ect

4. Instalar dependencias de la función:
   cd functions
   npm install
   cd ..

5. Desplegar:
   firebase deploy --only functions

Si Firebase pide actualizar el proyecto al plan Blaze, hay que habilitar facturación para continuar con Cloud Functions.

Después del despliegue debería aparecer la función:
coverageAlerts


PARTE 6 - COMPORTAMIENTO DE coverageAlerts
-------------------------------------------
Cada minuto revisa los 67 cursos.

- Entre 10 y 8 minutos antes:
  envía el recordatorio al Staff asignado.

- Si no hay Staff asignado:
  envía "Curso sin Staff asignado" a todos los dispositivos registrados.

- Desde la hora de inicio y durante los primeros 10 minutos:
  si check_start sigue en false, envía "Curso sin cubrir" a todos los otros integrantes del Staff.

Los campos reminder_10_sent_at y uncovered_alert_sent_at evitan repetir el mismo aviso.


PARTE 7 - FIREFOX / CHROME
---------------------------
GitHub Pages usa HTTPS, requisito para Web Push.
El navegador debe permitir notificaciones para el sitio.

En celulares, la compatibilidad exacta depende del navegador y del sistema operativo. Probá las notificaciones en los dispositivos reales antes del evento.


SI NO QUERÉS ACTIVAR BLAZE TODAVÍA
----------------------------------
La app sigue funcionando para:
- registro de Staff,
- agenda,
- asignaciones,
- confirmar cobertura,
- inicio/fin,
- avisos locales mientras la app está abierta.

Simplemente los avisos automáticos con la app completamente cerrada no serán confiables hasta desplegar la función programada.
